# Code Reviewer 审查 Prompt 模板

zapply 第 3c 步代码审查的**两用文档**:

1. **降级路径任务模板**:未安装 `zapply-reviewer`(zagents)时,填充占位符(`<...>`)后整体作为**内置 code-reviewer** 的任务描述。
2. **维度权威源**:本清单与 `zagents/agents/zapply-reviewer.md` 内置清单**镜像维护**——在这里改维度,必须双向同步到那边。

> ⚠️ 若已装 `zapply-reviewer`:它**自含同款清单与分层机制**,dispatch 时只给上下文四要素(change 路径 / 审查分支 / 方案约束 / craftsman 报告要点),**不要**把本模板正文灌给它,否则两套指令互相打架。

## 模板

```markdown
## 上下文

- Change 路径:<change-dir>
- 审查范围:<分支名> 相对 base 的完整 diff
- 方案约束:<设计约束——必做的、明确不做的、架构/分层约定>
- Craftsman 交付报告:<其报告要点——改动文件 / 测试结果 / 声明完成的任务>

## 任务(只读,不修改任何文件)

1. 设计约束核对:该做的没做、不该做的做了;UI 任务另核对是否严格遵循项目 DESIGN.md——视觉量经 CSS 变量消费、无硬编码 hex/px 新值、无与既定品牌冲突的样式决策
2. bug / 逻辑错误 / 边界遗漏:空/null、空集合、日期时区、字符编码、off-by-one
3. 安全问题(重点):注入、越权、敏感信息泄漏;**硬编码凭证 = blocker**
4. 架构合理性:项目分层约定、耦合度、循环依赖、抽象方式与既有形态一致
5. 设计原则与模式:SRP/OCP/DIP/Demeter;策略/工厂/观察者等使用恰当而非滥用
6. 硬编码魔法常量(重点):业务阈值/超时/重试次数/分页大小/状态码/枚举开关写死 = blocker(循环边界 i=0 等自明除外);硬编码路径/URL 同罪
7. 造轮子(重点),按阶梯核查:标准库/已有工具能覆盖却手写重实现 = blocker;非平凡需求(易错领域/数十行)不引成熟库执意手写 = suggestion;几行琐事引重库 = suggestion;擅自引入框架级重依赖 = blocker
8. 死代码与残留:未用 import/变量/函数、注释掉的代码块、不可达分支、调试 log/TODO/FIXME
9. 错误与资源处理:吞异常不打日志、连接/流/句柄未释放、错误处理偏离项目约定
10. 并发与数据一致性:共享状态竞态、漏 await、多步写无事务部分失败留脏数据
11. 性能隐患:N+1 查询、循环内 IO/重复计算、不必要的全量加载、大对象拷贝
12. 测试与兼容:遵循 design.md「测试策略」(分层/覆盖率目标/边界异常并发场景);公共接口破坏性变更及调用方同步
13. 代码臭味(重点,默认 suggestion):过长函数 / 过深嵌套 / 上帝类 / 超长参数列表 / 跨文件复制粘贴的重复逻辑段 / 布尔标志参数群 / 命名与意图脱节 / 用注释解释看不懂的代码;同域重复第三处出现、或阻碍下一步改造 → 升 **blocker**
14. 依赖与文档同步:新增依赖必要性/版本锁定/成熟度/同领域是否已有同类库;行为变更同步 README/API 文档
15. craftsman 报告属实性:声明的任务真的实现了吗?测试结果可信吗?
> 维度按项目技术栈裁剪:不适用的(如无数据库则无 N+1、纯前端无事务)明说跳过,不为凑数硬找问题。

## 输出格式

按严重度分级,每条给「文件:行 + 问题 + 理由」:

- **blocker**:必须修才能归档(bug / 安全问题 / 硬编码凭证 / 业务魔法常量 / 重复造轮子 / 明显偏离方案约束 / 破坏性变更)
- **suggestion**:同样下发修复,优先级低于 blocker(风格 / 微优化 / 可读性);确实不该修的由 craftsman 说明理由

没有 blocker 就明说"未发现 blocker",不要为了凑数报低价值问题(置信度过滤)。
```

## 使用说明

- **只读**:code-reviewer 不写任何文件,只返回审查报告;发现的问题由主智能体决定谁修
- **独立**:审查者不偏袒 craftsman 的自报,也不受主智能体"希望通过"的心态影响
- **门禁**:blocker 是归档硬门禁;suggestion 不改变门禁,但同样下发 craftsman 修复,逐条处理(修复或豁免;豁免受「豁免反腐」约束,由主智能体仲裁)
- **严重度只看问题本身**:当前 diff 引入且现有上下文可修的缺陷,一律进本轮修复清单——禁止以「可以以后做 / 下个版本」降级或移出清单
- 用户选择"重跑 craftsman"时,blocker + suggestion **全量**进入重跑 prompt 的"上一轮结果",标注优先级:blocker 先、suggestion 后
