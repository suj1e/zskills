# Code Reviewer 审查 Prompt 模板

zapply 第 3 步核实阶段(3b),起 code-reviewer 子智能体时使用。填充占位符(`<...>`)后,整体作为子智能体的任务描述。

## 模板

```markdown
## 上下文

- Change 路径:<change-dir>
- 审查范围:<分支名> 相对 base 的完整 diff
- 方案约束:<design.md 核心约束摘要——必做的、明确不做的>
- Craftsman 交付报告:<其报告要点——改动文件 / 测试结果 / 声明完成的任务>

## 任务(只读,不修改任何文件)

1. 核对 diff 是否偏离 design.md 约束:该做的没做、不该做的做了
2. 找 bug / 逻辑错误 / 边界遗漏 / 安全问题
3. 代码设计与架构合理性:新增代码是否遵循项目现有分层/模块约定?有无过度耦合、循环依赖、不合理抽象?新增的公共接口/工具函数签名是否与项目风格一致?
4. 代码风格与整洁度:命名是否清晰?函数/类是否单一职责?重复逻辑是否可抽取?是否有过长函数/过深嵌套?注释是否必要且不过度?
5. 核对 craftsman 报告是否属实:声明的任务真的实现了吗?测试结果可信吗?

## 输出格式

按严重度分级,每条给「文件:行 + 问题 + 理由」:

- **blocker**:必须修才能归档(bug / 安全问题 / 明显偏离方案约束 / 破坏性设计)
- **suggestion**:不阻塞归档(风格 / 微优化 / 可读性)

没有 blocker 就明说"未发现 blocker",不要为了凑数报低价值问题(置信度过滤)。
```

## 使用说明

- **只读**:code-reviewer 不写任何文件,只返回审查报告;发现的问题由主智能体决定谁修
- **独立**:审查者不偏袒 craftsman 的自报,也不受主智能体"希望通过"的心态影响
- **门禁**:blocker 是归档硬门禁;suggestion 不阻塞,汇总给用户看
- 用户选择"重跑 craftsman"时,blocker 条目逐条进入重跑 prompt 的"上一轮结果"
